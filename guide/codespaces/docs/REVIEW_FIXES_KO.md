# 검토 항목별 판단과 수정

기준: `codex_functional_spec_interview_data_checks.zip`에 대한 사용자 검토. 이상치 탐지용 별도 프로그램을 추가하지 않고 기존 문서 하네스를 수정했습니다.

| 항목 | 판단·처리 |
|---|---|
| 1. 문서 생성 실패 후 재실행 잠금 | 실제 결함. 종료·정리가 확인된 실패를 기록하고 다음 실행에서 새 리비전으로 재시도합니다. 이전 실패 이력은 삭제하지 않습니다. 정상 완료 결과의 저장 복구는 재호출 없이 유지합니다. |
| 2. 40개 제한에서 비교 후보 생략 | 실제 결함. 기준선 비교·시계열, 비유한값·혼합, IQR·결측 순으로 안정 정렬한 뒤 자릅니다. 생략 수는 계속 표시합니다. |
| 3. `minLength` 호환성 | 당시 Codex CLI 0.155.1 및 `gpt-6-astra` 설정에서 원래 스키마로 실제 호출이 성공했습니다. 당시 환경의 확정된 오류는 아니었습니다. 중복 제약은 제거하고 Python의 빈 문자열·형식 검증을 유지했습니다. |
| 4. 오프셋 없는 시각 | 개선. 기준·감시 자료 둘 다 오프셋 없는 시각이면 비교하고, 숫자·오프셋 있음·오프셋 없음의 축 혼합은 계속 거부합니다. 실제 시간대는 추정하지 않습니다. |
| 5. 한국어 출력 | 세 프롬프트에 한국어 질문·문서를 명시하고 새 답변 문서의 라벨도 한국어로 바꿨습니다. 기존 실제 답변과 영문 기록의 바이트·해시는 보존합니다. |
| 6. 행·라인·절 언급 거부 | 실제 과도한 검사. 데이터 행, 생산 line, 인터뷰 절을 허용했습니다. 데이터 후보는 파일·timestamp·열·값으로 구체화하도록 안내합니다. |
| 7. 미정 상태로 진행 | 담당자가 특정 항목의 보류와 진행을 명시한 실제 답변을 주면, 그 항목을 진행 차단 질문에서 제외하고 문서의 '미결 사항'에 남기도록 했습니다. 단순 '모른다'는 동의로 처리하지 않습니다. |
| 8. 기능명세 수정 요청 | 최소안 반영. INTERVIEW.md에 '6. 문서 확인 중 받은 수정 요청(실제 답변)'을 추가했습니다. 기능명세서만 독립 수정·승인하는 새 경로는 추가하지 않았습니다. |
| 9. Python 버전 | 3.9 이상을 허용합니다. `start`를 포함한 진입점도 3.9 미만을 먼저 거부합니다. 실제 실행 검증한 버전은 검증 보고서에 기록합니다. |

## 실패 후 재실행

실패한 호출이 확실히 종료되고 정리가 끝났을 때만 새 호출을 허용합니다. 요구사항·기능명세서의 상태 파일이나 실패 폴더를 직접 지우지 마세요. 남은 문제 시간 안에서 같은 `requirements` 명령으로 재개합니다. 한 번의 실행 안에서 실패를 무한히 재호출하지 않습니다.

정상 완료됐지만 모델의 JSON/문서 형식이 잘못된 응답도, 검증 가능한 실행 기록을 보존한 상태로 다시 생성할 수 있습니다. 출처가 확인되지 않는 응답이나 변조된 실행 기록을 형식 오류로 간주해 넘기지는 않습니다. 실행 중 입력이 바뀌면 옛 결과를 채택하지 않으며, 필요한 재분석·재확인 단계를 거칩니다.

모델 실행 중에는 문제 폴더 안 파일을 저장하지 마세요. 수정할 때는 종료·정리가 끝난 뒤 수정하고 다시 실행하세요. 자동 동기화 폴더는 내용·속성이 예기치 않게 달라질 수 있으므로 일반 로컬 폴더를 권합니다.

## 보류와 수정 요청의 의미

'미정으로 두고 진행'은 값을 확정했다는 뜻이 아닙니다. 문서에는 보류 항목, 실제 답변의 근거, 아직 정하지 않은 범위를 남기며 수치나 합격 기준을 임의로 채우지 않습니다. 이 판단은 모델 지시와 실제 답변에 의존하며, 최종 문서 확인은 계속 필요합니다.

인터뷰 6절은 실제 수정 요청을 기록할 자리입니다. 인터뷰가 바뀌면 문서 입력도 바뀌므로 기존 요구사항·기능명세서 확인이 무효화됩니다. 기능명세서의 표현만 고치는 요청도 현재는 이 경로를 거칩니다.

## 스키마 확인 근거

[OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 `minLength` 제한은 fine-tuned 모델의 추가 제한으로 안내되어 있습니다. strict 스키마 전체가 언제나 이 키워드를 거부한다고 단정할 수는 없습니다. 실제 설치된 CLI와 모델로도 확인했으며, 통과 범위와 테스트 결과는 [검증 보고서](../validation/REPORT.md)에 기록했습니다.
