# 하네스 내부의 데이터·문서 검사

별도 이상치 탐지 프로그램을 설치하거나 실행하지 않습니다. `requirements` 단계가 입력 검사 요약을 만든 다음, 분석 모델이 그 요약과 문제·인터뷰·실제 답변을 함께 읽습니다.

## 입력 데이터 지정

CSV를 `problem-project` 안에 저장하고 해당 폴더의 `config.json`에 상대 경로를 적습니다.

```json
{
  "spec": "SPEC.md",
  "interview": "INTERVIEW.md",
  "data_files": ["data/measurements.csv"],
  "model": "gpt-6.1-sol",
  "reviewer_model": "gpt-5.6-terra",
  "codex_command": ["codex.exe"],
  "problem_time_limit_seconds": 9600
}
```

`data_files`가 빈 목록이면 숫자 데이터 검사는 하지 않습니다. 문제 설명과 인터뷰 검사는 계속합니다. UTF-8 CSV의 첫 행은 열 이름이어야 합니다. 데이터 파일도 `SPEC.md`에 참고 자료로 적어 두세요.

위 예시는 새 Windows 과제의 기본 설정입니다. macOS/Linux에서는 문제 접수 전에 `codex_command`를 `["codex"]` 또는 실제 호환 CLI 경로로 설정하세요. 제한은 접수부터 160분이며, 이미 9000초로 시작한 과제는 기존 설정과 저장된 150분 마감을 유지합니다. 진행 과제에 이 예시를 덮어쓰지 말고 원래 설정·입력·호출 기록을 보존하세요. 데이터 요약을 읽는 문서 분석 모델은 공통 `model`인 `gpt-6.1-sol`입니다. 이후 개발 단계의 독립 검토는 `reviewer_model`인 `gpt-5.6-terra`를 사용합니다. 문서 분석 전에 `model` 또는 실행 명령의 `--model`로 공통값을 바꿀 수 있지만, 별도로 지정한 검토 모델은 바뀌지 않습니다. Codex CLI 로그인 정보와 API 키는 배포하지 않습니다.

비교 가능한 과거 기준 CSV를 갖고 있다면 선택적으로 `"data_baseline": "data/baseline.csv"`를 추가합니다. 기준 파일을 감시 데이터와 같은 파일로 지정할 수 없습니다. 기준 파일을 지정했다고 해서 그 자료의 단위·운전 조건·대표성이 검증된 것은 아닙니다.

## Python이 확인하는 것

| 검사 | 결과의 의미 |
|---|---|
| 빈칸·null·none | 결측 표시. 허용되는 결측인지 담당자에게 확인 |
| NaN·무한값 | 유효한 유한 측정값으로 취급하지 않음 |
| 한 열의 숫자·문자 혼합 | 의도한 자료형 확인 필요 |
| 숫자 열의 1.5×IQR 밖 값 | 이번에 추가한 탐색적 이상값 후보. 업무상 오류로 확정하지 않음 |
| timestamp/value 형식의 시각 중복·역순 등 | 시계열 입력 상태 확인 필요. 임의 정렬·보정하지 않음 |
| 명시한 과거 기준의 I/MR 한계 밖 값 | 고정된 기준과 비교한 후보. 기준의 업무상 타당성은 별도 확인 |

IQR은 파일 안의 유한 숫자로 계산하며 최소 4개 값이 있을 때 검사합니다. 표본 수가 작거나 분포가 특별하면 후보가 실제 오류와 다를 수 있습니다. 기준이 없는 상태에서 센서별 정상 범위나 고장 여부를 만들어 내지 않습니다.

I/MR 비교는 `timestamp`, `value` 열이 있는 시계열을 대상으로 합니다. `group`, `regime`이 있으면 그 조합별 기준을 사용하고, 없으면 단일 기본 계열로 취급합니다. 감시 시점은 해당 그룹의 기준 구간 이후여야 합니다. 표본 부족·변동 0·시간축 불일치·비교 불가능한 조건은 정상 판정 대신 확인이 필요한 상태로 남깁니다. 일정한 표본 간격도 관측 자료에서 추정한 값이며, 확정된 측정 계약으로 취급하지 않습니다.

오프셋 없는 시각(예: `2026-11-05 10:00:00`)은 기준·감시 자료 둘 다 오프셋 없는 시각을 쓰면 비교합니다. 컴퓨터의 시간대를 임의로 적용하지 않습니다. 숫자 시각, 오프셋 있는 시각, 오프셋 없는 시각을 서로 섞으면 비교를 거부합니다. 실제 시간대의 의미는 담당자에게 확인해야 합니다.

검사 자체가 CSV를 고치거나 행을 삭제하지 않습니다. 검사 요약과 입력 파일 해시는 모델 호출 기록에 함께 저장되며, 데이터가 바뀌면 이전 문서 확인을 재사용하지 않습니다.

## 모델이 확인하는 것

- 문제 원문, 인터뷰, 실제 답변, 성공 기준 사이의 모순
- 빠진 조건, 단위, 임계값, 예외 처리와 우선순위
- 확정되지 않은 AI 제안이나 미정 목표가 실제 합의처럼 섞여 있는지
- 데이터 이상 후보가 허용되는 값인지, 수정해야 하는 오류인지 판단할 근거

필요한 내용을 기존 질문 흐름에 포함합니다. 담당자가 실제 답변으로 해결한 내용은 반복해서 묻지 않도록 합니다. 문서 의미에 대한 모델의 판단을 기계적으로 보장하는 것은 아니므로, 요구사항과 기능명세서 확인 단계는 유지합니다.

## 요약 크기와 한계

현재 입력 상한은 감시 CSV 8개, 파일당 2 MiB, 기준 파일을 포함한 합계 8 MiB, 파일당 데이터 10,000행·64열, 시계열 그룹/조건 128개입니다. 상한을 넘기면 일부만 읽고 완료하지 않고 명시적으로 중단합니다. 자료를 의미 있는 범위로 나누고 `data_files`를 조정하세요.

모델에는 최대 40개 검사 항목과 항목당 최대 3개 예시를 전달합니다. 더 많은 항목이 있으면 생략 수를 표시하고, 생략된 내용을 모두 검토했다고 판단하지 않도록 지시합니다. 긴 CSV를 통째로 반복해서 프롬프트에 넣지 않습니다.

40개를 고르기 전에 **기준선 비교·시계열 → 비유한값·혼합 자료형 → IQR·결측** 순으로 정렬합니다. 같은 우선순위에서는 원래 순서를 유지합니다. 중요한 비교 결과가 보조 열의 결측·IQR 후보 뒤로 밀리지 않도록 합니다.

## 참고한 자료

사용자가 제공한 `unified_anomaly_kit_python39_renamed.zip`의 입력 검사와 고정 기준 I/MR 개념을 참고했습니다. 해당 묶음은 PKJthecreator/probe-kit, dogsa33/cofa-kit, hjyeo30/hackathon-agent-harness 등의 출처를 기록하고 있습니다. 이번 `.harness/data_checks.py`는 표준 라이브러리로 작성한 입력 진단 함수이며, 원본 프로그램·CLI·함수 본문을 통째로 포함하지 않습니다. IQR 검사는 이번 하네스의 탐색적 입력 확인용으로 새로 추가한 것입니다.
