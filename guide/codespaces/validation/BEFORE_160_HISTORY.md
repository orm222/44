# Python 3.9용 재배포 확인

실행 코드는 직전 ZIP과 바이트 단위로 같습니다. README의 실행 기준·명령을 Python 3.9로 명확히 했으며 개인 IDE 설정은 포함하지 않습니다. 3.13 검사 기록은 같은 코드의 과거 호환성 검증 자료입니다.

이번 재배포는 Python 3.9.25로 생성했습니다. 모든 Python 파일의 동일성과 3.9 문법 컴파일, 세 진입점의 도움말, 기존 버전 검사 테스트 1개를 다시 확인했습니다. 전체 361개 검사는 코드가 같은 직전 배포판의 결과를 유지하며 이번에 중복 실행하지 않았습니다. 명령과 실제 결과는 [재배포 확인 기록](python39-release.json)에 있습니다.

아래는 그대로 보존한 직전 전체 검증 기록입니다.

최종 재검사 반영 결과 실패 0건. 기존 276개 회귀검사와 새 검사·통합·문서 회귀를 포함합니다. 건너뛴 검사의 이유는 Windows 환경의 심볼릭 링크 생성 권한 부족이며 각 로그에 명시되어 있습니다. 같은 검사를 여러 번 돌린 횟수는 테스트 수에 중복 합산하지 않았습니다.

`python -B -m unittest discover -s harness-kit/.harness/tests -v`와 동등한 모듈별 실행으로 검사했습니다. 독립 임시 프로젝트를 사용하는 모듈을 버전별 최대 네 개 병렬 실행했고, 통합 과정에서 수정한 모듈은 최종 코드로 다시 실행했습니다. [Python 3.9 기록](assurance-py39/summary.json)과 [Python 3.13 기록](assurance-py313/summary.json)에 명령 대상·결과·로그 해시를 보관했습니다.

## 이번 변경의 실제 검증 범위

- 실행기·설치된 Python 패키지·로컬 포트의 읽기 전용 조사. 자동 설치나 외부 접속 없음.
- 실제 CSV의 연결 키 중복, 관계 위반, 미매칭, 빈 키, 예상 조인 행 수. 읽기 상한 초과를 통과로 처리하지 않음.
- 입력 키 발생 횟수와 사용·제외·보류 처리대장의 정확한 다중집합 대조. 확장된 최적화 결과의 행 수와 입력 수를 잘못 비교하지 않음.
- 실제 로컬 subprocess가 생성한 CSV/JSON으로 처리 누락·중복·미지 키·생성 파일 누락/손상을 검출.
- 필수 제약 우선, 기준선 포함 최대 세 후보의 최소화/최대화 비교, 독립 정확값이 있는 작은 표본의 오차·입력 해시 검증. 정확값이 없으면 미측정으로 기록.
- 새 계약의 스키마·웹/비웹 분기·담당 작업 선택·실패 시 검토 진입 차단·세 번 실패 후 사용자 재승인.
- 실제 자식 프로세스의 성공·실패·로그/산출물 증거·중단 복구. 종료가 불명확하면 재호출하지 않음.
- 웹에만 브라우저 검사 호출. 실제 로컬 테스트 서버와 명시적인 모의 브라우저 worker로 서버 소유권·종료·실패·환경 미준비·PNG/JSON 증거 검증.
- 계획·구현·최종 승인 유지, 기존 최초 접수부터 150분과 호출 예산 유지, 필수 검증 없이 완료 차단.
- 계획서와 검증 보고서에 적용/제외 이유·승인 계약·실측 결과·로그/이미지 경로 표시. 사용자가 쓴 UNDERSTANDING 마지막 열 보존.

통합 검사에서 생성 산출물 오류와 원본 자료/환경 미준비를 구분하고, 종료·정리가 입증된 브라우저 환경 실패의 새 시도를 허용하도록 보완했습니다. 보호 파일 변경과 종료 증거 미확인은 계속 중단 사유입니다.

최초 병렬 실행에서는 Python 3.9 브라우저 복구 테스트 1건이 실패했고, Python 3.13 기존 프로세스 테스트의 임시 폴더 정리 중 Windows 파일 잠금 오류가 1건 발생했습니다. 브라우저 테스트는 최초 실행과 복구 결과를 모두 표시하도록 진단을 보강했고, 최종 14개를 두 버전에서 다시 실행해 통과했습니다. 기존 프로세스 모듈은 코드·검사를 변경하지 않은 재실행에서 10개가 통과했습니다. 두 실패의 정확한 재발 조건은 확정하지 못했으며 제한 시간이나 보호 검사를 완화하지 않았습니다. 최초 로그와 결과도 `assurance-initial-py39/`, `assurance-initial-py313/`에 보존합니다.

## 실제 실행과 모의 실행의 구분

이번 배포판 검증에서 유료 모델을 호출하지 않았습니다. 모델 역할·승인 흐름의 응답은 오프라인 대체 실행기를 사용하며, 일반 테스트와 데이터 생성기는 실제 Python subprocess로 실행했습니다. 실제 모델의 특정 과제 해결 성능은 측정하지 않았습니다.

이 환경에는 Playwright가 설치되어 있지 않아 **실제 브라우저 DOM·렌더링 성공을 검증하지 못했습니다.** 서버 준비/정리와 기록 검증은 실제 프로세스로 검사하고 브라우저 성공 결과는 명시적인 테스트 대체 worker를 사용했습니다. 웹 과제 실행 때 Playwright 또는 브라우저가 없으면 BLOCKED이며 완료하지 않습니다. 설치를 자동으로 실행하지 않습니다.

이 세션에서는 실제 Docker 엔진을 사용할 수 없어 **이미지 빌드·컨테이너 구동 성공을 확인하지 못했습니다.** Docker/Compose 검사는 기존 모의 실행 기반 경계·복구 테스트입니다. 실제 과제에서는 기존 필수 Docker 검사와 종료 증거가 있어야 완료됩니다.

업무별 목적함수·제약 측정 코드는 모델이 작성하고 독립 검토자가 확인합니다. 표본에서 통과한 결과를 모든 입력의 최적성이나 업무 전체의 정확성으로 확대하지 않습니다. 입력 상한과 계약 예시는 [추가 검사 안내](../docs/ASSURANCE_KO.md)를 참고하세요.

## 보존과 배포 확인

기존 이상치 검사 `data_checks.py`와 인터뷰·요구사항·저장·시간·프로세스·일반 검사 도우미는 기준 ZIP과 바이트 단위로 동일함을 확인했습니다. 기존 개발 흐름 연결부·계약·문서 renderer만 확장했고, 추가 검사 코드는 별도 모듈로 두었습니다. 이전 승인 계획에는 검사를 임의로 추가하지 않으며 기존 계약 없음(LEGACY)을 명시합니다. 새 계획 또는 승인된 재계획에서 새 계약이 적용됩니다.

[이전 개발판 기록](DEVELOPMENT_HISTORY.md), [기존 문서 단계 기록](INTAKE_HISTORY.md)을 보존합니다. ZIP CRC, 전체 파일 SHA-256 및 두 Python 버전의 압축 해제본 CLI 도움말을 검사합니다. 현재 배포 파일 목록은 최상위 `SHA256SUMS.json`을 기준으로 확인하세요.
