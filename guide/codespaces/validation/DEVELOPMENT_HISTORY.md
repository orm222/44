## 실제 모델·Docker 실행의 한계

이번 확장판의 **유료 모델 호출은 실행하지 않았습니다.** 역할·스키마·실패·중단·재개는 실제 로컬 자식 프로세스와 오프라인 Codex 대체 실행기로 검사했습니다. 모델이 실제 과제의 코드를 올바르게 작성한다는 성능 평가는 별개입니다.

현재 세션의 Docker CLI는 설정 파일 접근/기본 엔진 연결에 실패했습니다. 따라서 **실제 이미지 빌드·컨테이너 구동 성공은 검증하지 않았습니다.** Docker/Compose 경계 테스트는 명시적인 모의 실행기를 사용합니다. 실제 과제 실행에서는 엔진·필수 검사 증거가 없으면 BLOCKED이며 완료 처리하지 않습니다.

외부 프레임워크의 의존성 설치와 업무별 정확성은 생성된 계획·검사 계약과 실제 실행 환경에 따라 확인해야 합니다. 테스트 명령은 승인 후 로컬에서 실행되므로 격리된 임시 의존성 환경을 사용하도록 안내합니다. Python AST는 함수 존재를 확인하고, 비Python 코드의 호출 순서·저장소 의미는 검토 에이전트가 확인합니다.

## 기존 기능 보존과 기록

기존 실행 코드 변경은 launcher의 run/develop 연결과 requirements 승인 화면/완료 안내에 한정했습니다. data_checks.py, boundary.py, clarify.py 및 기존 저장·시간·프로세스 도우미는 원본과 같습니다. 새 개발 기능은 development*.py 모듈로 분리했습니다.

과거 이름 변경·문서 단계 검사·실제 schema 확인 결과는 [이전 검증 기록](INTAKE_HISTORY.md)에 보존했습니다. 과거 실제 모델 호출을 이번 개발/Docker 전체 실행으로 계산하지 않습니다. 현재 배포 파일의 해시는 최상위 SHA256SUMS.json을 기준으로 확인하세요.
