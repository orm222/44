# 검증 결과

검증일: 2026-11-05

## 현재 전체 ZIP에 반영한 이름 변경

이 배포본에는 최신 `data_checks.py`를 포함합니다. 함수·변수 이름 22개와 내부 딕셔너리 키 10개, 총 158개 중 32개(약 20.25%)의 이름을 변경했습니다. 외부 함수·CSV·설정·반환 JSON 계약은 유지했습니다.

이름 변경 후에는 Python 3.9.25와 3.13.5에서 기존 데이터 검사 20개 및 데이터 연결 흐름 4개, **각각 24개가 통과**했습니다. 테스트 중 소스도 바뀌지 않았습니다. `renames.json`, `rename-tests.json`, `rename-*.log`가 해당 기록입니다.

아래의 178개 전체 회귀검사는 이름 변경 전 배포본의 검사입니다. 현재 파일을 적용한 뒤 178개 전체 검사를 다시 실행한 것은 아닙니다. 이번 전체 ZIP의 모든 Python 파일은 이름 변경 후 검사에 사용한 파일과 해시가 같습니다. 패키징하면서 검증 설명·기록·`SHA256SUMS.json`만 갱신했습니다. 과거 테스트 기록의 전체 스냅샷에 있는 문서·해시는 그 검사 당시 기준이며, 현재 배포 파일의 해시는 최상위 `SHA256SUMS.json`을 따릅니다.

| 실행 환경 | 검사 수 | 결과 |
|---|---:|---|
| Python 3.9.25 | 178 | 통과 |

실패·오류 없이 통과했습니다. 각 버전에서 같은 테스트를 실행했고, 검사 전후 실행 코드·프롬프트·스키마·테스트 파일의 SHA-256이 같음을 확인했습니다. `tests.json`에 테스트 ID, 그룹별 소요 시간, 실제 검사한 파일 해시가 있으며 `py39-*.log`와 `py313-*.log`에 unittest 출력이 있습니다. 해시 경로는 ZIP 최상위 폴더 기준입니다.

기존 기능과 함께 다음 경계를 검사했습니다.

- 실패 종료·타임아웃 뒤 새 리비전 재시도, 원래 시계·이전 실패 기록 보존
- 빈 문서·잘못된 JSON·잘못된 결과 형식의 재시도
- 실행 중 또는 성공 직후 입력 변경 시 재분석·필요한 요구사항 재확인
- 완료 결과의 저장 중단 복구, 종료 불명확·정리 미완료·기록 변조 시 차단
- 40개 요약 제한에서 I/MR 후보 우선 전달과 생략 수 유지
- 오프셋 없는 시각끼리 비교, 서로 다른 시각 축의 혼합 거부
- 데이터 행·생산 line·인터뷰 절 질문 허용, 실제 답변 원문 보존
- 기존 영문 답변 기록의 해시 호환, 새 한국어 라벨
- 명시적 보류 답변을 기록하고 두 문서 확인 단계 유지
- 문서 빈 문자열·공백·잘못된 자료형 차단, 구형 Python 조기 거부

`data-before-after.json`은 넓은 CSV와 오프셋 없는 시각에 대한 수정 전후 재현 결과입니다. OS 전용 테스트나 tmux는 추가하지 않았습니다.

## 이전 배포 단계의 실제 Codex 호출

설치된 Codex CLI **0.155.1**, 기존 ChatGPT 로그인, 선택된 모델 **gpt-6-astra**로 원래의 `minLength: 1` 요구사항 스키마를 전송했습니다. 실제 호출이 종료 코드 0으로 끝났고, 지정한 키와 비어 있지 않은 한국어 문자열이 있는 JSON을 반환했습니다. `live-schema-summary.json`과 `live-schema-answer.json`에 결과를 보관했습니다.

이는 원래 스키마가 이 환경에서 허용됨을 확인하는 짧은 호환성 검사입니다. 전체 문서 생성·복구 회귀검사는 로컬 모의 모델을 사용했습니다. 실제 모델의 한국어·보류 판단 정확도, 실전 문서 품질, 현장 이상 탐지 정확도를 검증했다는 의미는 아닙니다.

## 실행 방법

최상위 폴더에서 해당 Python 버전으로 실행합니다.

```text
python -B -m unittest discover -s harness-kit/.harness/tests
```

배포 과정은 ZIP CRC, 배포 파일과 검사 소스의 일치, Python 3.9 문법을 확인한 뒤 압축을 풀어 `--help`, `time-status`, `requirements --status`, `start`를 두 Python 버전으로 실행합니다. 이 확인에서 실패하면 배포 완료로 보고하지 않습니다.
